# Dark double-bridge sunglasses — engines 20–24

The reported photo previously yielded only the right lens as `front`. Filled
dark lenses were not apertures in the foreground-mask hierarchy.

The new image-driven path verifies a balanced, solid dark lens pair at multiple
contrast levels, subtracts those regions, and requires stable measured metal
rims and a third bridge aperture. It does not use project IDs or template shapes.
Analysis is normalized to a bounded working resolution and mapped back to the
source coordinates. Nose-pad protrusions are excluded using measured rim width.
At isolated tangent contacts a half-analysis-pixel clearance prevents open mesh
walls; this is a bounded geometric approximation, not new photographic detail.

Verified the actual source at 540, 1080 and 2160 pixels, and rejection of two
unframed dark blobs. An isolated front-only draft generates closed beveled
geometry with consistent normals. Merchant approvals and stored models are
unchanged. Evidence: `artifacts/dark-sunglasses/{before,after}.png`, analysis JSON
and `draft/model.glb`, generated by `scripts/verify_dark_sunglasses.py`.

Scope: white-background, dark-lens double-bridge fronts meeting the evidence
checks. This is not a claim of universal sunglasses detection, recovered lens
optics, or verified live-AR appearance. The original front-only diagnostic did
not include arms; the follow-up below now includes the right arm.

## Pale side arm follow-up (engine 21)

The fixed seed landed in the dark lens. Nearby seed recovery now applies to
chromatic as well as neutral frames, still requiring the outer tip and three-mask
agreement. A normalized retry handles smaller sources. Bounded shaft
regularization reduces threshold notches only when the observed upper edge fits

The actual side photo passes at 540/1080/2160 pixels and mirrored orientations,

## Lens tint and nose pads (engine 22)

Default clear-lens material caused the dark lenses to disappear. Generation now
estimates a uniform tint from paired dark lens interiors only when lens settings
are unchanged defaults. Trimmed samples exclude darker rear arms and highlights;
custom settings are preserved. Removed the undocumented 65% opacity ceiling.
This is appearance estimation on white, not a measurement of optical transmission.

Visible nasal protrusions removed from the metal-rim silhouette now supply two
reviewable pad anchors. Approved anchors generate separate pads regardless of
frame category; absence of supported pad evidence still does not invent pads.
The existing pad ellipsoids approximate shape/depth; they are not manufacturing
geometry. The default pad tint for this automatic route is clear neutral rather
than beige. Reanalyze the front to obtain these new anchors, then regenerate.

`tint-pads.png` is a CPU color/geometry diagnostic with flat lens alpha blending,
not a browser or AR screenshot, and it does not simulate pad transparency or
physical lens optics. The draft contains only the independently traced right arm.

## Viewer color, visible pad review, and contour refinement (engine 23)

The prior CPU render hid a real discrepancy: source sRGB color bytes were used
as linear glTF factors and the browser lit the estimated lens material. Estimated
lenses now export linear factors and use the shared unlit, non-tone-mapped
preview/AR policy, with front-face rendering to avoid double alpha blending.
`node scripts/test-lens-color-policy.mjs` tests the actual viewer policy.

Detected pad silhouettes now appear in blue in quick review and are editable
parts in Advanced. Generation extrudes these reviewed visible silhouettes,
instead of using the anchor-only generic oval. Their hidden thickness remains
an explicit 1.2mm approximation. Raster teeth are smoothed in bounded vector
space before thin-rim clearance checks. The existing 2x pass alone had retained
raw fallback segments when its topology checks failed.

Re-analyze front, review the blue pads, approve and regenerate; reload the page
to load the updated viewer policy. Browser pixels are not verified by the CPU
diagnostic or the Node policy test.

## Dense curves and edge/pad appearance (engine 24)

Adds dense arc-length curve sampling with bounded Gaussian regularization before
meshing. Suggestions stay within 1.75 normalized source pixels; area and topology
guards remain. This changes the curve supplied to geometry, not merely SVG line
rendering. Added a noise-reduction/displacement regression test.

Thin-rim texture cleanup now preserves narrow observed edge samples instead of
eroding them into pale fill. A dark optical border is constructed only where
successive inward image bands demonstrate contrast, and is mapped from the photo;
no black border is added to uniform lenses. Pads now carry their observed front
photo detail rather than an untextured neutral material.

Rear-arm contrast/pose is not pixel-matched. The supplied inner photo is a partial
frame close-up; it does not establish the complete inner-arm finish. Transmission
and invisible arm cross-sections remain inferred. The diagnostic intentionally
contains only the verified right arm, not an invented opposite arm.
